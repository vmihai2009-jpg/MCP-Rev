# Facade detail: mistakes made, why, and what to do instead

Read this before running or changing any `facade_*`, `window_look` or `facade_detail_pass` step. Every mistake found on a real run goes
in here in the same commit that fixes it (Mihai's rule, 2026-11-25: "make sure everything you do is registered in the repo so it
can memorise all mistakes and what to do"). A row is: what was seen, the cause, the rule, where it lives, and whether it is fixed.
Survey to Revit's own lessons are in `DWG-Survey-to-Revit-3D/docs/LESSONS.md`.

Run these lessons come from: 7 Swallow Place / 251-259 Regent Street (Plowman Craven), `SwallowPlace_Demo.rvt`, 2026-11-25.

## How to check one facade (the order that works)

1. `facade_list`, `elevation_index` (all elevations of the sheet, not only the ones S2R found), `section_index`.
2. `survey_autofix` openings. Then `facade_detail_pass dry_run: true`; read the log (style per facade).
3. `facade_detail_pass`. Then per facade `facade_correspondence image: true` and look at it.
4. `dwg_image facade: F.. along_mm / z_mm` for any bay that looks wrong; `element_geometry` for any element whose parameters and picture disagree.
5. Record anything new here before moving on.

## Tool for the next session

`tools/mcp-call.ps1 -Tool <name> -ArgsJson '{...}'` calls a hub tool over HTTP, waits for the job and prints the answer, so a big answer
(`facade_detail_map`, `query_elements` with 1000 rows) can be read by a script instead of flooding the chat. Used to count classical
features per facade and to collect element ids by Comments tag.
